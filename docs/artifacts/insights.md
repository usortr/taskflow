## 4.2. Список инсайтов (≥3)

### Инсайт 1: «Оценка vs Факт — главная боль бизнеса»
**Наблюдение:** В Trello/Jira есть учёт времени, но нет **встроенного сравнения** `estimate_h` vs `fact_h` с автоматическим флагом перегрузки.  
**Решение:** Мы ввели `over_alloc_flag` — система сама показывает, кто перерабатывает.  
**Ценность:** Тимлид видит проблему **до** того, как сотрудник выгорит.

---

### Инсайт 2: «SLA-контроль через `closed_at`, а не `current_date`»
**Наблюдение:** В большинстве трекеров просрочка считается по текущей дате. Но если задача ещё открыта — она не просрочена, она **в работе**.  
**Решение:** Мы считаем просрочку только по факту закрытия: `closed_at ≤ due_date`.  
**Ценность:** Избегаем ложных срабатываний и паники.

---

### Инсайт 3: «Идемпотентность — не роскошь, а необходимость»
**Наблюдение:** При повторном импорте CSV Jira/Trello создают дубликаты. Пользователь вынужден вручную чистить базу.  
**Решение:** Наш импорт идемпотентен по ключам (`user_id`, `task_id`, `(task_id, user_id, date)`).  
**Ценность:** Пользователь может перезагружать данные без страха.

---

### Инсайт 4: «2 роли достаточно для MVP»
**Наблюдение:** PDF (стр. 124) прямо указывает 2 категории доступа: «исполнители — только свои задачи, менеджеры — все».  
**Решение:** Мы упростили до `teamlead` + `worker`.  
**Ценность:** Соответствуем §1.5 (MVP ≤5 операций) и не усложняем ролевую модель.
