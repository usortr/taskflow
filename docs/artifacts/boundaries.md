## 4.4. Границы системы (≥3)

### Граница 1: Функциональные границы

**Входит:**
- Учёт задач (4 статуса: todo → in_progress → review → done)
- Учёт трудозатрат (часы по задаче)
- Аналитика загрузки (`over_alloc_flag`)
- SLA-контроль (`on_time_rate`)
- Экспорт CSV (`workload.csv`, `sla_tasks.csv`)

**Не входит:**
- Интеграции с внешними трекерами (Jira, Trello, Asana)
- Управление зависимостями задач (эпики, блокировки)
- WIP-лимиты
- Уведомления (email, Telegram)
- Мобильное приложение

---

### Граница 2: Ролевые границы

**Входит:**
- 2 роли: `teamlead` (суперпользователь) и `worker` (исполнитель)
- `teamlead`: видит все задачи, импортирует/экспортирует, назначает задачи
- `worker`: видит только свои задачи, меняет статус, пишет часы

**Не входит:**
- Роли «Контролёр» и «Администратор» (функционал покрыт `teamlead`)
- Детальная ролевая модель (RBAC с правами на уровне полей)
- Авторизация с JWT/паролями (замена — переключатель ролей в UI)

---

### Граница 3: Данные и интеграции

**Входит:**
- Импорт CSV (`users.csv`, `tasks.csv`, `time_logs.csv`)
- Экспорт CSV (`workload.csv`, `sla_tasks.csv`)
- Синтетические данные (T1, T2)
- Мок-API (GET /tasks, POST /time-logs)

**Не входит:**
- Реальные интеграции с трекерами (REST API Jira/Trello)
- Обмен с 1С:Документооборот или внешними АС
- Обработка реальных ПДн (персональных данных)
- Хранение коммерческой тайны

---

### Граница 4: Технические границы

**Входит:**
- Платформа: 1С:Предприятие 8.3 (бэкенд)
- UI: Figma-прототип + мок-API (фронтенд)
- Данные: CSV (UTF-8, `,`, `"`)
- Git: GitVerse (репозиторий, PR, релизы)

**Не входит:**
- Прод-деплой (только учебный стенд)
- Микросервисная архитектура (всё в одном приложении)
- Docker/Kubernetes (развёртывание вручную)
- CI/CD (опционально, не обязательно)
