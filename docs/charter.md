# 2. 📜 УСТАВ ПРОЕКТА

## 1. Инициатор и обоснование

**Инициатор:** Кафедра МИРЭА (представитель «Заказчика»)  
**Обоснование:** Внутренние процессы управления задачами в учебных/рабочих командах требуют прозрачности загрузки и контроля сроков. Существующие решения (Jira, Trello) избыточны для учебных целей и не дают аналитики по загрузке.

## 2. Цель проекта

Разработать MVP-решение на платформе 1С с UI-прототипом, которое:
- Обеспечивает учёт задач и трудозатрат
- Визуализирует загрузку команды
- Контролирует соблюдение сроков (SLA)
- Экспортирует отчёты в CSV

## 3. Область применения

- Учебные команды (5–10 человек)
- Малые рабочие группы (до 20 человек)
- Пилотирование в рамках дисциплины «Основы проектной деятельности»

## 4. Ключевые стейкхолдеры

| Стейкхолдер | Интерес |
|---|---|
| Тимлид | Контроль загрузки, распределение задач |
| Исполнитель | Прозрачность своих задач, учёт времени |
| Куратор/преподаватель | Приёмка по KPI и golden-файлам |
| Команда разработки | Учебный проект, оценка по рубрикам |

## 5. Ограничения

- **Временные:** 8 недель (W1–W8)
- **Ресурсные:** 5 человек, учебная лицензия 1С
- **Технические:** Без интеграций с внешними АС, без ПДн, только синтетика
- **Бюджетные:** 0 руб. (учебный проект)

## 6. Критерии успеха

- Все артефакты (§7 PDF) представлены
- ≥80% acceptance-критериев выполнено
- Экспорт CSV совпадает с golden (±1%)
- Демо-видео 3–5 мин записано
- Релизы v0.1 (W5) и v1.0 (W8) выпущены

## 7. Полномочия Project Lead

P3 (fullstack) уполномочен:
- Согласовывать MoSCoW с куратором
- Утверждать изменения через change-request
- Распределять задачи внутри команды
- Принимать артефакты на Gate
